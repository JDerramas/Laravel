# 🚀 Engineering Daily Devlog — September 28, 2026

## 🏛️ PHASE 14: PLUGNMEET UNLIMITED MEETING ARCHITECTURE, LIVEKIT CLOUD OFFLOADING & DOCKER STORAGE REDIRECTION

### 1. Executive Summary & Problem Root Cause
Noong sinubukang magsagawa ng virtual classroom lecture sa NPC ELMS (`live_room.php`), nakaranas ang user ng sapilitang pagdiskonekta sa timer na **01:08:22** na may abisong *"Disconnected: The meeting has ended."*

#### Mga Pangunahing Sanhi (Root Causes):
1. **Public Demo Server Hard Limit**:
   * Ang application ay dating naka-point sa pampublikong demo server (`https://demo.plugnmeet.com`). May built-in hard limit ang demo server na humigit-kumulang 60 minuto upang protektahan ang kanilang pampublikong bandwidth.
2. **Drive C Storage Exhaustion & Docker Panic**:
   * Nang simulan ang Docker Desktop para sa sariling PlugNmeet stack, bumagsak ang libreng espasyo ng **Drive C sa 0.03 GB (30 MB)** dahil sa laki ng WSL virtual disk (`docker_data.vhdx` na umabot sa 3.7 GB) at naka-install na lumang Ollama application (2.76 GB). Nagdulot ito ng `containerd panic: SIGBUS: bus error`.
3. **Port Conflict sa Port 8080**:
   * Ang default port ng PlugNmeet API (8080) ay okupado ng umiiral na Local AI process (`llama-server.exe`).

### 2. Architectural Upgrades & System Interventions

#### A. C: Drive Rescue & NTFS Hard Symbolic Link Migration
Upang mabawi ang espasyo at maiwasan ang mga susunod pang disk crashes:
1. **Ollama Deletion**: Tinanggal ang hindi na ginagamit na Ollama application at local cache mula sa `C:\Users\Lovi\AppData\Local\Programs\Ollama` at `C:\Users\Lovi\.ollama` (Nabawi ang **+2.79 GB**).
2. **Docker WSL Virtual Disk Redirection**:
   * Kinopya ang `docker_data.vhdx` mula C: patungong `D:\DockerWSL\disk\docker_data.vhdx` (191 GB Free).
   * Gumawa ng NTFS directory symlink gamit ang `mklink`:
     `C:\Users\Lovi\AppData\Local\Docker\wsl\disk\docker_data.vhdx <<===>> D:\DockerWSL\disk\docker_data.vhdx`
   * **Resulta**: Lumaki ang libreng espasyo ng C: mula **0.03 GB patungong 6.50 GB FREE**, habang ang lahat ng susunod na Docker containers at images ay ligtas nang maiimbak sa Drive D.

#### B. PlugNmeet Server Docker Deployment (`D:\plugnmeet-server`)
* Na-clone ang opisyal na `plugNmeet-server` repository sa `D:\plugnmeet-server`.
* Na-configure ang core services:
  * **Database**: Na-configure sa `mysql:8.0` na may initialized schema mula sa `install.sql`.
  * **Cache / In-Memory State**: `redis:8.6`
  * **Pub/Sub Engine**: `nats:2.14-alpine` sa ports 4222 at 8222.
* **Port Remapping**: Inilipat ang PlugNmeet API port mula **8080 patungong 8085** upang maiwasan ang banggaan sa `llama-server.exe` (Local AI LLM).
